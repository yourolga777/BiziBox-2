#### Этап 2 — множественные метки (ОТЛОЖЕНО, внесено в план)
- [ ] `life_sphere` → набор меток (junction `contact_spheres`), контакт может быть «Личное» И «Работа» одновременно; спам — эксклюзивный флаг. База: `docs/user-guide/classification-concepts.html` (метки + статус «Новое»). Делаем строго ПОСЛЕ Этапа 1.
- [ ] **Модель (согласовано 06.10.2026):** метка = тип контакта (`contact_types`, уже M2M); сфера — атрибут метки и папки. Папки → несколько на контакт (новая M2M `contact_folders`, сколько угодно). Сфера контакта = производная (явные сферы через junction `contact_spheres` ∪ сферы папок ∪ сферы меток); можно «сфера без папки». **Автосвязь папка↔метка** (кладёшь в «Поставщики» → метка «Поставщик», и наоборот). Спам — эксклюзивный флаг, сохранять предыдущий набор меток/папок для возврата. Каналы — одна метка; загрузка только выбранной папки/подпапки по кнопке. «Другое» — как есть (без меток/папок). Карточка контакта показывает ВСЕ классификации (сфера + папка + подпапка). Счётчики считаются в обоих разделах.
- [ ] **Фикс счётчиков каналов во Входящих:** при выборе «ТГ» у почты 0 и наоборот — считать канальные счётчики из неотфильтрованного списка (`allChats`/`spamChats`), а не из `chats`.
- [ ] **DnD подпапок:** подпапки тоже можно перетаскивать в строке (порядок), как верхние папки.
- [ ] **Поставщики ↔ Каталог (двусторонняя связка, согласовано 06.10.2026).** «Поставщик» — метка/тип контакта (реализуется через множественные метки этого этапа), папка «Поставщики» (сфера «Работа») — источник поставщиков в Каталоге. Контакт с меткой «Поставщик»/в папке «Поставщики» → показывается в Каталоге как поставщик. Новый поставщик из Каталога (импорт товаров или «Добавить поставщика») → контакт автоматически получает метку «Поставщик» и кладётся в папку «Поставщики». Удаление: товары автоматически **НЕ** удаляются — удалил поставщика → товары остаются без поставщика; удалил товары → поставщик остаётся без товаров. **Архивация поставщика** — как у товаров («В архив»): поставщик уходит из Каталога и из папки «Поставщики» (снимается метка «Поставщик»), но контакт не удаляется — если у него есть другие метки, он остаётся в соответствующих папках классификации; товары при архивации поставщика не удаляются.

## Главный принцип для ВСЕХ модулей

**Всё новое делаем «как Задачи в IziBox».** Это эталонная выкройка, на которую равняемся:

- Модель: `owner_id` + сущность + `deleted_at` (мягкое удаление/архив) + `created_at/updated_at`.
- Сервис: методы `get_all / get_deleted / get_detail / create / update / delete / restore / bulk_delete / bulk_restore`.
- Роутер: тонкий, делегирует в сервис; эндпоинты `GET /`, `GET /archive`, `GET /{id}`,
  `GET/POST /{id}/comments`, `POST /`, `PATCH /{id}`, `DELETE /{id}`, `POST /{id}/restore`, `POST /bulk-*`.
- Схемы: `XResponse`, `XDetailResponse`, `XCreate`, `XUpdate`, `XCommentCreate/Response`.

Эталоны для копирования структуры:

- `backend/app/models/task.py`
- `backend/app/repositories/task.py`
- `backend/app/services/task_service.py`
- `backend/app/routers/tasks.py`
- `backend/app/schemas/task.py`
- `frontend/src/pages/Tasks.tsx`
- `frontend/src/components/tasks/`
- `frontend/src/api/tasks.ts`
