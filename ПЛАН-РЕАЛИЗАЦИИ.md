## Журнал новых задач / решений
- **Решение:** удалён `scripts/seed_izibox_tasks.py` — IziBox-специфичный seed-скрипт TAUSIK (создавал epic `izibox-v1`), не нужен в BiziBox 2.0.
- **Решение:** `CHANGELOG.md` оставлен как историческая летопись IziBox (не переименован), `ПЛАН-РЕАЛИЗАЦИИ.md` ссылается на исходник IziBox — оба исключены из проверки «нет остатков бренда».
- **Факт:** в IziBox уже были остатки `bizibox`/`BIZIBOX` (след форка) — при переименовании они задваивались; исправлено (9 файлов).
- **TAUSIK:** проект инициализирован как `bizibox-2-0`, задача `step0-base` **закрыта** (done, 5/5 шагов, все проверки зелёные).
- **Багфикс:** в ручной проверке были 500 на онбординге/почте/дашборде. Причина: `config._ensure_env_file()` при первом запуске создавал `backend/.env` из `.env.example`, где `ENCRYPTION_KEY=dev-encryption-key-not-for-production` — невалидный Fernet-ключ, и `crypto.py` его не игнорировал → `encrypt()` падал RuntimeError → онбординг/почта 500, `.active_login` не создавался → дашборд/входящие 500. Фикс: `crypto.py` использует `config._DEFAULT_ENCRYPTION_KEYS`. TAUSIK-задача `bugfix-500-channels`.
- **Решение:** реальные `TELEGRAM_API_ID/HASH` и прокси (socks5 127.0.0.1:10808) из старого BiziBox вписаны в `backend/.env` нового проекта (в `.gitignore` уже есть). Сессию Telegram из старого приложения решили **не переносить** — подключать заново.
- **Решение:** классификация контактов переведена с `contact_type` на `life_sphere` (personal/work/spam) — спам теперь сфера, а не флаг. Типы контактов — множественные (M2M через `contact_type_templates` + `contact_contact_type_association`). Папки привязаны к сфере (`sphere`), вложенные (`parent_id`); две системные «Каналы» (personal/work) разрешены через unique-индекс `(owner_id, category_key, sphere)`. Миграция `e0f1a2b3c4d5`; seed папок schema-agnostic (initial-миграция сидит без `sphere`/`contact_type`). Системные шаблоны типов сидятся в `init_db`. Правки охватили backend (репозитории/сервисы/роутеры/тесты) и frontend (`life_sphere`, `contactSphereMeta`, фильтры, FormDialog, mocks, 16+ тест-файлов). Проверки зелёные.

## Главный принцип для ВСЕХ модулей

**Всё новое делаем «как Задачи в IziBox».** Это эталонная выкройка, на которую равняемся:

- Модель: `owner_id` + сущность + `deleted_at` (мягкое удаление/архив) + `created_at/updated_at`.
- Сервис: методы `get_all / get_deleted / get_detail / create / update / delete / restore / bulk_delete / bulk_restore`.
- Роутер: тонкий, делегирует в сервис; эндпоинты `GET /`, `GET /archive`, `GET /{id}`,
  `GET/POST /{id}/comments`, `POST /`, `PATCH /{id}`, `DELETE /{id}`, `POST /{id}/restore`, `POST /bulk-*`.
- Схемы: `XResponse`, `XDetailResponse`, `XCreate`, `XUpdate`, `XCommentCreate/Response`.

Эталоны для копирования структуры:

- `backend/app/models/task.py`
- `backend/app/repositories/task.py`
- `backend/app/services/task_service.py`
- `backend/app/routers/tasks.py`
- `backend/app/schemas/task.py`
- `frontend/src/pages/Tasks.tsx`
- `frontend/src/components/tasks/`
- `frontend/src/api/tasks.ts`

## Правила процесса (TAUSIK/SENAR)

- Перед правкой кода — активная задача с целью и AC (QG-0).
- Готово — только после `tausik verify` и закрытия задачи (QG-2).
- Ветки: `feature/XXX-short-name`. Коммиты: `feat: | fix: | docs: | refactor: | test:`.
- git commit/push — только после подтверждения.
- Навигация по коду: зависимости — `scripts.graph`, поиск символов — `codebase-rag.search_code`.
