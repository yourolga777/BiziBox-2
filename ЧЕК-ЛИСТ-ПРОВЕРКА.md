## A. Сферы и классификация

- [+] **Сид папок по сферам.** *Где:* Контакты → боковая панель папок. *Как:* раскрыть дерево по сферам. *Ожидание:* у «Работы» — Заказчики/Поставщики/Сотрудники; у «Личного» — Группы и др.; **нет** «Партнёры»/«Подрядчики»; «Каналы» — только в секции «Каналы».
- не нужно писать рядом с папкой слово «системная», это перекрывает название папки
- давай сделаем везде, где выбираем классификацию, не два поля выбора, а одно, где видны все сферы с папками и подпапками. Можно сделать с раскрывающимися плюсиками, чтобы не портить визуал.
- [+] **Папки привязаны к сфере в форме классификации.** *Где:* карточка контакта → классификация (сфера + папка). *Как:* выбрать сферу, открыть select «Папка». *Ожидание:* в списке только папки этой суффиксом `(Личное)`/`(Работа)`; «Без папки» первым.
- [+] **Вкладки «Каналы» и «Спам» пустые при входе.** *Где:* Входящие → вкладка «Каналы» / «Спам». *Как:* перезапустить приложение, открыть вкладки. *Ожидание:* не грузятся автоматически — только счётчик и кнопка **«Загрузить каналы»** / **«Загрузить спам»** (у спама подпись «Загруженные ранее диалоги видны сразу»).
- [-] **Кнопка загрузки работает, данные остаются.** *Как:* нажать «Загрузить каналы»/«Загрузить спам» → дождаться списка → перезапустить приложение → открыть вкладку снова. *Ожидание:* загруженное отображается сразу (из БД), кнопка доступна для докачки свежего; ошибки (напр. таймаут) показываются красным текстом, не роняют UI.
- После выхода из приложения при повторном входе каналы и спам должны быть пустыми, но в них остались ранее загруженные. Они должны сохранятся в где-то в базе, чтобы при нажатии «загрузить» они не скачивались заново.
- Добавь вариативность: загрузить новые и загрузить ранее загруженные

- [+] **Спам без папок, снятие спама возвращает сферу.** *Как:* в карточке спам-контакта снять спам. *Ожидание:* контакт возвращается в прежнюю сферу/папку (`previous_life_sphere`), а не в «Личное» по умолчанию.
- [+] **«Другое» — виртуальная секция.** *Как:* убрать у контакта сферу и папку (или найти контакт из бывших «Партнёров» после миграции). *Ожидание:* контакт виден в секции «Другое», у неё нет своих папок в дереве.
- в контактах нет папки другое для не классифицированных, есть только во входящих, нужно добавить


## B. Единый компонент папок (FolderTree)

- [+] **Одинаковое дерево в «Контактах» и «Входящих».** *Где:* Контакты → боковая панель; Входящие → режим управления папками. *Ожидание:* оба места показывают одно и то же дерево с группировкой заголовков сфер (та же структура, тот же порядок).
- [+] **Выбор папки фильтрует.** *Как:* кликнуть папку. *Ожидание:* папка подсвечивается, список контактов/диалогов фильтруется; клик по той же папке снимает выбор (ожидается поведение как раньше).
- При выборе верхнеуровневной папки должны отображаться все контакты/сообщения из всех подпапок
- При разворачивании папок и выборе подпапки развернутый блок не должен сворачиваться, должно быть видно, где мы
- [+] **Создание папки/подпапки из «Входящих».** *Как:* режим управления → «Создать папку» (или дочернюю). *Ожидание:* выбор секции (в т.ч. «Каналы») + выбор родителя из кандидатов этой суффикса; новая папка появляется в дереве обоих мест без перезагрузки.
- Есть плюсик, надо заменить надпись на «создать папку»
- [+] **Редактирование из обоих мест.** *Как:* в дереве нажать редактирование (иконка/клик) — в «Контактах» и в «Входящих». *Ожидание:* открывается модалка переименования + выбора цвета (пресеты); сохранение обновляет папку в обоих местах сразу.
- [+] **Системные папки нельзя удалить.** *Как:* навести/попытаться удалить системную папку (с `category_key`). *Ожидание:* кнопка удаления недоступна/скрыта; пользовательские — удаляются.
- [+] **Drag&drop порядок папок.** *Как:* перетащить строку папки за любую её часть. *Ожидание:* зоны drop — верхняя/нижняя половина строки (вставка до/после); порядок меняется; после перезагрузки порядок сохраняется (`POST /api/folders/reorder`).
- [+] **Перетаскивание только среди соседей по уровню.** *Как:* попытаться бросить дочернюю папку на папку из другой сферы/другого родителя. *Ожидание:* перестановка не происходит (siblings-only).
- [-] **Контакт перетаскивается на папку.** *Как:* из списка контактов перетащить строку контакта на папку в дереве. *Ожидание:* контакт перемещается в эту папку.
- не перетаскивается

## C. Идентификаторы контактов и отправка

- [-] **Блок «Другие идентификаторы» в карточке.** *Где:* карточка контакта. *Как:* открыть контакт с несколькими адресами (или после мержа дублей). *Ожидание:* блок «Другие идентификаторы» показывает доп. TG ID / TG-логины / email-и, а не текст заметок.
- объединяю контакты, где все данные разные, поле имя должно дополниться обоими именами через пробел, должны появиться дополнительные поля телефон, мейл и тг, если они заполнены у обоих контактов
- [-] **Мерж переносит каналы в идентификаторы.** *Как:* выполнить мерж дублей, где у вторичного был свой `telegram_id`/`telegram_username`/`email`/`phone`. *Ожидание:* у объединённого контакта эти адреса видны в «Другие идентификаторы»; в заметках мусора нет.
- не понимаю, где это
- [ ] **Селектор получателя — только при нескольких адресах.** *Где:* Входящие → диалог → строка ответа (композер). *Как:* открыть диалог контакта с 1 адресом, затем — с 2+. *Ожидание:* при 1 адресе селектора нет; при 2+ над полем ввода появляется **«Получатель:»** с вариантом «По умолчанию (адрес контакта)» и альтернативами (TG ID, TG @, email из contact.identifiers).
- не понимаю, где это

- [-] **Отправка на выбранного получателя.** *Как:* выбрать альтернативный адрес → отправить сообщение; затем выбрать «По умолчанию» → отправить ещё. *Ожидание:* оба уходят; при выборе альтернативного TG-логина (`@user`) резолвится в числовой ID на бэке (сообщение доставляется); сброшенный/дефолтный вариант ведёт себя как раньше.
- [-] **Сброс выбора при смене диалога.** *Как:* выбрать альтернативного получателя → открыть другой диалог. *Ожидание:* селектор снова «По умолчанию», старый выбор не «залипает».
